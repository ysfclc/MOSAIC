## Referential integrity rules

- A media item's locations are removed when that media item is deleted (`CASCADE`).
- Collection memberships are removed when either the collection or media item is deleted (`CASCADE`).
- Playback history and queue entries retain their snapshots when a media item is deleted (`SET NULL` on the optional media reference).
- Media identity is unique by the pair `(sourceId, sourceItemId)`; source IDs are not interchangeable.
- Parent entity updates use Room `@Upsert`, not destructive `REPLACE`, to avoid triggering FK cascades.

## Migration policy

1. Never edit a released schema JSON by hand.
2. Any entity change must bump `MosaicDatabase.version`, add an explicit Room `Migration`, and check in the newly generated schema version.
3. Keep every prior schema version in the schema directory.
4. Add migration tests that create a database from the previous schema, insert representative rows, migrate, and assert values, relationships, bookmarks, resume positions, queue snapshots and timer state survive.
5. Do not add `fallbackToDestructiveMigration`.
6. Do not cut playback history, queue or timer over from legacy preferences until Room read/write parity, reopen/process-death behavior and migration tests pass.
