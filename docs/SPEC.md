# MOSAIC requirements and coverage registry

This file turns the narrative requirements in [PRODUCT_SPEC.md](PRODUCT_SPEC.md) and the locked north star in [MOSAIC_PRODUCT_VISION.md](MOSAIC_PRODUCT_VISION.md) into traceable requirement IDs. It is an index, not a competing product vision. Implementation references point to the current source snapshot; test references identify executable evidence. A source/contract test does not replace real-device acceptance.

## Status rules

- **DONE** — implementation, relevant behavior/failure-path tests and documentation are linked; all applicable device/source acceptance gates have evidence.
- **PARTIAL** — useful implementation and some automated evidence exist, but a test, operational acceptance, compatibility or documentation gate remains open.
- **TODO** — the product requirement has no demonstrated implementation path yet.
- CI verification means source checks, Python tests, Android unit tests, lint and APK assembly pass. It does not mean the target phone or a named external provider has been tested.

## Known reconciliation items

1. `TASKS.md` previously marked RSS, radio, browser media handoff and native video surface as entirely TODO. Their narrow initial implementations exist now; the relevant tasks are IN PROGRESS, not DONE.
2. `PROVIDER_CAPABILITY_MATRIX.md` distinguishes MOSAIC Player, Browser Player, External Player and Link Only. Preserve those distinctions. A delegated external session does not join MOSAIC's native queue.
3. `AdBlockPolicy.kt` no longer exempts whole YouTube/Spotify pages or their unrelated third-party requests. Known third-party ad/tracker domains are blocked on those pages. Google ad infrastructure is blocked by default and has a narrow YouTube-page compatibility exception based on the existing player-delivery concern; real-device compatibility testing is still required.
4. No device-based requirement is DONE until a corresponding Redmi Note 12 Pro 5G outcome is recorded in the relevant acceptance checklist/matrix.
